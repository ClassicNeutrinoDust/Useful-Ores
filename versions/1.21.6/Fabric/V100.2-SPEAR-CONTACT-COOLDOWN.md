# V100.2 — Exact 1.21.11-style spear contact cooldown

This release keeps the proven V100.1 server-authoritative kinetic spear implementation and corrects the contact-cooldown state machine.

## Problem

V100.1 used a simple timestamp cooldown after every successful hit. That permits the same target to be damaged again after 10 ticks even if the spear has never actually lost contact with that target. During one continuous sprint/dash, this can produce several hits on one mob and excessive total damage.

## Correct behavior

The 1.21.11 `minecraft:kinetic_weapon` component defines `contact_cooldown_ticks` as the cooldown after hitting **and losing contact** with an entity. The state is therefore now:

1. First contact + valid kinetic conditions → hit.
2. Continue intersecting the same target → no additional hits.
3. Target leaves the spear contact ray → start 10-tick cooldown.
4. Target re-enters before 10 ticks → still no hit.
5. After the cooldown expires, a later re-contact may hit again.

This prevents a single uninterrupted dash from repeatedly damaging the same entity while preserving the intended ability to hit again after breaking contact and re-engaging.

## Files changed

- `SpearChargeCombat.java`
  - Replaced unconditional timestamp pruning with per-target contact state.
  - Tracks `hit`, `touching`, and `cooldownUntil`.
  - Starts the 10-tick cooldown only on contact loss.
  - Leaves V100.1 range, speed, damage calculation, sprint reliability, and jab behavior unchanged.

## Reference

Minecraft Java Edition 1.21.11 documents `contact_cooldown_ticks` with a default of 10 ticks and describes it as the cooldown after hitting and losing contact with an entity before it can be hit again.
