# V100.1 — Spear server-contact reengineering

## Root cause
V99.x used the client crosshair target packet to trigger damage. That made the hit inherently depend on packet arrival timing and allowed ground/entity collision to invalidate a contact that visually occurred on the client.

## V100.1 architecture
- Server runs the kinetic contact query every active-use tick, matching the 1.21.11 KineticWeapon ownership model.
- Client sends only its pre-collision velocity sample. It cannot nominate a victim.
- Server raycasts against current server entity state every tick.
- AttackRange updated to the documented spear model: normal min reach 0.4, max 4.5; creative min 0.0; hitbox margin 0.25.
- Most recent client velocity is used for kinetic speed when fresh; server delta movement is the fallback.
- Removed the client movement-segment victim search and network-triggered damage path.
- Jab path remains server-side and the V99.1 animation system is untouched.

## Research basis
Mojang's 1.21.11 notes define `minecraft:kinetic_weapon` as a charge attack whose damage is applied along a ray every tick while the item is used. The migration primer documents the server-side `KineticWeapon#damageEntities` dispatch and the spear AttackRange values described above.

## Expected effects
Ground sprint impacts are no longer dependent on a client victim packet arriving in the same server tick. Damage should occur on the server contact tick rather than after a network round trip, and creative flight should not produce delayed post-contact damage.
