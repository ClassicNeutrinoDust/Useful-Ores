# V99.4 — spear charge re-engineered from vanilla 1.21.11

## Root causes established from the 1.21.11 bytecode

The 1.21.11 `KineticWeapon#damageEntities` implementation does four important things that the previous backport did not reproduce exactly:

1. It runs from the active item-use tick, not an independent server tick listener.
2. It uses the spear's `AttackRange` ray segment. The built-in spear range is min 2.0, max 4.5, creative max 6.5, with 0.125 hitbox margin.
3. It uses `Entity` delta movement multiplied by 20 and projected onto the view vector for speed and relative speed.
4. Each condition has its own duration window; holding RMB does not terminate the item use merely because a condition's window expired.

## V99.4 changes

### Charge timing
`SpearItem.onUseTick` is now the sole server-side driver for kinetic charge processing. The old `START_SERVER_TICK -> ACTIVE_USES -> tick()` damage loop was removed from mod initialization.

The remaining-use-ticks argument is converted directly to `ticksUsed`, matching vanilla's `useDuration - remainingUseTicks` calculation.

### Target selection
The previous body-box/cone detector was discarded. V99.4 implements a backport of the vanilla `ProjectileUtil.getHitEntitiesAlong` + `AttackRange` geometry:

- start = eye + view * 2.0
- end = eye + view * 4.5 (6.5 in creative)
- block clip truncates the segment
- candidate hitboxes are inflated by 0.125
- segment/AABB intersection determines ordered hits
- projectile-hit and player-harm restrictions are applied

The 2.0 minimum reach is intentional: that is the vanilla spear's actual minimum attack range.

### Kinetic calculation
The attacker and target velocity vectors are `deltaMovement * 20`, then projected onto the attacker's current view vector.

For a player:

`relativeSpeed = max(0, attackerSpeedAlongView - targetSpeedAlongView)`

Damage remains:

`floor(relativeSpeed * damageMultiplier) + attackDamage`

The existing material-specific profile values are retained because they already match the vanilla spear table.

### Long holds
The item use remains active while RMB is held. The dismount, knockback, and damage conditions independently expire according to their own durations, exactly like the vanilla condition object. The entire charge session is not killed when the first condition window expires.

### Sprint / Creative movement
The old expression-level movement patches were not sufficient because they depended on specific internal `isUsingItem()` branches. V99.4 additionally returns the original raw `Vec2` from `LocalPlayer.modifyInput` at method HEAD whenever a spear is being charged.

That directly emulates `UseEffects(..., horizontalMovementMultiplier=1.0)` and bypasses the generic 1.21.10 item-use slowdown before it can mutate input. The sprint-stop hook remains disabled for spear use.

This also applies while flying in Creative, where the same input path was observable as a reduced flight speed.
